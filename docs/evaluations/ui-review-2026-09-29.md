# grok-4.6 UI/交互审查（2026-09-29，基线 main 4efd309）

素材：docs/evaluations/ui-tour-demo-transcript.txt（离线 demo 真实 PTY 录屏）与 linux-pty-transcript.txt。原文如下。

## 1. Feedback gaps

### `/verify` in demo/read-only never shows an approval, then eats the `y`

**File:** `src/tools/permissions.ts:15`, `src/core/agent.ts:252–270`, `src/ui/App.tsx:183`, `src/ui/transcript.ts:214`

**Tour:** after `/verify echo ok`, the screen is `✗ bash echo ok (0ms)` / `read_only` / `已停止：verification_failed` / status `失败` — no `允许执行命令？` box. The driver then sent `y` (the same key the Linux PTY used for a real approval). That `y` landed in the composer, concatenated with the next `/task`, and became a **new user goal** `y/task` that started another demo run (`ui-tour-demo-transcript.txt` 832–945).

A human who followed README `/verify` in `icy --demo` does the same: types `y` into an empty prompt, or hits Enter on `y` and starts a junk task. `read_only` and `verification_failed` are untranslated. Nothing says “离线/只读不能跑 bash 验收，请去掉 `--demo`/`--read-only`”.

### `/kill` unknown id is an English machine code; short ids look like PIDs

**File:** `src/ui/App.tsx:170–176`, `src/core/agent.ts:60–67`, `src/ui/transcript.ts:23–31`

**Tour:** `/kill 1234` → `无法终止后台进程 1234：process_not_found`. Usage text (only if you omit the argument) asks for `icy-process:id` or an 8-char prefix. `/ps` prints `pid 12345` in the same line as `icy-process:11111111`. Unix muscle memory is `/kill 12345`. That path is the same `process_not_found`. `process_ambiguous` is also raw English.

Idle `/kill` also flashes `⠋ Ready 0s · Esc 取消` (`App.tsx:121, 293`) before the error — “Ready” plus a cancel affordance for a lookup that Esc does not cancel (`localAction` does not use `controller`).

### Approval deny has no “你拒绝了” line

**File:** `src/tools/permissions.ts:39`, `src/ui/transcript.ts:203–214`, Linux PTY `=== Denied command ===`

After `n`, the transcript shows `✗ bash …` / `permission_denied` and the model keeps going (`思考中…` → `已根据实际工具结果结束本轮`). Status stays `执行中`. Codex/Claude Code both say the command was denied in the user channel. Here the only signal is a dim yellow snake_case tool error.

### `/continue` / `/verify` failure clobbers the status bar

**File:** `src/ui/App.tsx:126–131, 150, 183`, `src/core/agent.ts:247–255`

`/continue` always posts `继续原任务，将开启并记录新预算…` **before** `agent.continue`. If there is no task, that notice is a lie, then `runTask` catch sets `Stopped`, `turn 0`, `tokens —`. Same clobber for `/verify` with no task (`请先执行一个任务，再指定验收命令。`). Dual-pane `taskState` can still be the old task while the footer says `Stopped`.

### Resume mismatch vs resume success

**Mismatch (good-ish):** `src/core/agent.ts:53` + `App.tsx:185–186` keep the current view and notice `恢复需要相同工作区、provider、model 和 baseUrl…` (tested in `tests/ui-task.test.ts:154`).

**Success gap:** `resumeSession` returns `unknownProcesses` (`agent.ts:46–56`) and the UI **drops it** (`App.tsx:191`). Notice is only `已恢复会话 <uuid>；N 个未完成调用已标记`. Linux PTY wraps mid-sentence:

```
! 已恢复会话 ebb2b741-…；0
个未完成调用已标记。
```

A restored live PID (`pidAlive: true`, `identity_unconfirmed`) is not called out in that banner. You only find it later in `/ps` / process lines at the **bottom** of the rebuilt transcript (`transcript.ts:113` appends all processes after all messages).

### Budget / stop reasons stay internal

**File:** `src/ui/App.tsx:109`, `src/ui/transcript.ts:67–69, 140–142`, `src/core/agent.ts:14, 145–154`

`已停止：token_budget` / `budget_exceeded` / `max_model_turns` / `verification_failed` / `cancelled`. Footer becomes `达到限制` or `失败` with no “用 /continue 开新预算”. `/task` prints `最近检查点：stopped` and `停止原因：completed` — `stopped`/`completed` are storage enums. Dual pane: `停止：max_model_turns` (`App.tsx:300`). After a successful model turn the user still sees `已回答 · 未验证`; after a failed `/verify` the **old** `/task` notice still says `已回答 · 未验证` while the footer says `失败` (tour 694 vs 830).

### Process events vs `/ps`

Start/exit lines exist (`transcript.ts:13–21`, tested). They are dim, mixed with `!` notices, and restored out of order. `/ps` status is `running`/`killed`/… except `未确认`. No “已向 pid 发送终止” distinct from the later `process` event.

### Slash output is append-only `!` sludge

**File:** `App.tsx:52, 142, 148–149`

`/help`, `/task`, `/ps`, `/kill` errors, `/sessions` all become permanent notices. Tour after `/help`→`/task`→`/ps`→`/kill` still shows “当前会话没有任务状态记录” **and** “没有后台进程” **and** `process_not_found` while a real task is running (tour 424–454). Same `!` prefix for help, errors, and info.

### Ctrl+T is silent; `/thinking` is not

**File:** `App.tsx:59–61, 143–145, 241`

`/thinking` notices `思考内容已展开`. Ctrl+T (the key the footer advertises) does not. Footer always `Ctrl+T 思考`, no 展开/收起 state.

## 2. Discoverability

### `/help` is a truncated README

**File:** `App.tsx:142`, `src/ui/commands.ts:2–18`, `src/cli.tsx:19–45`

Help dump in the tour: command one-liners plus `↑↓ Tab Esc` / `Ctrl+T Ctrl+O PgUp/PgDn`. Missing, all of which a first-time user hits on day one:

| Missing | Where it actually lives |
|---|---|
| Y / A / N, “must page to last page” | README 快捷键; `App.tsx:288` |
| Esc 取消 vs Ctrl+C 退出 | README; `App.tsx:231–233` |
| Alt+Enter / Shift+Enter 多行, Ctrl+A/E/U/K | README; `Composer.tsx` |
| `/kill` ID vs pid, 8-char prefix | README; only empty-arg usage |
| `/verify` blocked in 只读/演示 | nowhere in `/help` |
| `/thinking expanded\|collapsed` | palette only after `/thinking ` |
| `/sessions status= answered,failed` | command description, no example |

`icy --help` lists slash names with no arguments (`cli.tsx:41`) and no approval/exit-code story.

### Palette (`matchCommands`)

**File:** `commands.ts:19–26`, `App.tsx:45–46, 281–294`

Prefix match on the **command token only**. `/k` → `/kill`. A space closes the menu (`/verify `.startsWith fails), so the usage hint vanishes exactly when you type the argument. No fuzzy match: `/hepl` → `未知命令`. While a run is active, `matches` is forced empty (`App.tsx:45`), so `/ps` has no palette — you must already know it.

Enter submits `selectedCommand?.command`, not the typed buffer (`App.tsx:294`). Safe for `/task`. Tab on `/thinking` inserts `/thinking ` and Enter then fires `/thinking expanded` (first submenu item), not toggle.

`/kill` description is `终止后台进程` — no `<id>`. `/verify` is `指定并执行验收命令，沿用 shell 审批` — no “会改工作区 / 只读不可用”. `/continue` does not say “不重放工具” in the palette (only after submit, and then even on failure).

### `/ps` / `/kill` / `/continue` / `/verify` for a first-timer

- `/ps` empty: `没有后台进程。` No pointer to `/kill` format.
- `/ps` populated: leads with **pid**. Kill does not accept pid.
- `/continue`: no preview of remaining todos/budget before it starts a new run.
- `/verify`: in workspace-edit, approval appears (Linux PTY). In demo, it does not (above). README “沿用 shell 审批” is what the tour driver believed.

### Detached approval under-explains risk

**File:** `App.tsx:264–266, 286–289`

Foreground: `bash 在主机执行，可访问工作区之外的资源。`  
Detach **replaces** that with `输出写入磁盘；命令会在当前轮结束后继续运行。` plus `最长 N 分钟，输出写入会话目录`.

Missing on the detach card: host-escape (same as foreground), 30‑minute cap as a hard max, no extra sandbox, `~/.icy/sessions/<id>/processes/` path, 16 MiB log, no stdin, crash → EPIPE. `A 本会话允许` does not say “同一 command + cwd + timeout + detach”；`/new` rebuilds the registry and drops grants (`agent.ts:45`). A daily Codex user will treat A as “allow bash this session”.

Y/A ignored until last page (`App.tsx:238`) with copy on earlier pages — acceptable. Typing `y` on page 1 is silent; the leftover-key problem is worse when **no** dialog mounted (demo `/verify`).

## 3. Interaction flaws

### Run-time composer: looks like Claude Code, behaves like a trap

**File:** `App.tsx:136–138, 233, 290–294`, `Composer.tsx:12, 66`

Tour during a run:

```
❯ ⠋ 执行中 0s · Esc 取消
    输入你的目标…
```

Composer stays mounted with the idle placeholder. Typing is accepted. Enter on a follow-up keeps the draft and appends `运行中：只接受 /ps 和 /kill；Esc 取消当前运行。` (`tests/ui-processes.test.ts:64` encodes this). There is **no persistent hint** until you submit something invalid. Claude Code queues; Codex is explicit about wait/cancel. This is the worst of both: it invites a new goal, then scolds.

Esc with a half-typed `/verify` or follow-up **aborts the run** (`App.tsx:233`: clear-draft only if `!running`). Second-Esc-to-cancel is not implemented; first Esc is cancel. That will destroy a long tool loop.

`/task`, `/thinking`, `/help`, `/todo` are also refused while busy. Checking budget or expanding thinking mid-run is a normal CC habit.

Idle `/sessions`/`/kill` reuse the same spinner (`Ready 0s · Esc 取消`) though Esc does not abort `localAction`.

### `y` + next command (composer never grabbed by a missing modal)

Covered in §1. After a failed `/verify`, the composer is idle; approval keys are ordinary text. Tour: `❯ y` then `❯ y/task`.

### Composer editing

**File:** `Composer.tsx:35–68`

- Single-line viewport, newlines as `↵` — workable, painful for a pasted patch.
- `key.delete` is backspace (`Composer.tsx:57`). Forward-delete does not exist.
- No word jump / word delete.
- 20 000 grapheme cap and message are correct (`tests/composer-limits.test.ts`).
- History is only `agent.run` prompts (`App.tsx:214`). You cannot ↑ to retrieve `/verify npm test`. First ↑ after a prompt works because `historyIndex` is set to `length`; empty history is a no-op.
- Esc idle clears a `/…` draft, not a normal draft (`App.tsx:233`).
- Placeholder `' 输入你的目标…'` has a leading space; empty prompt renders as `❯   输入你的目标…` (tour line 8).

### Approval paging / model wizard / session switch / thinking

- Paging to last page before Y/A is implemented and tested (`tests/ui.test.ts:27`). Dialog **replaces** the transcript (`App.tsx:278`), so you cannot see why the model issued the command.
- Wizard: Esc from url/key closes the whole wizard, not one step (`ModelWizard.tsx:72–73`). Testing paints “测试文本响应…” and “测试工具调用…” at once (`:97`) — not sequential. No skip-test. Apply notice says `--resume` not `/resume` (`App.tsx:254`).
- `/resume` replaces the transcript (good). `/clear` has no confirm.
- `/thinking` with empty demo reasoning: two blocks of `本次接口未返回可见思考内容。` (tour 1477–1484). Ctrl+O expands **all** tools, not one.

## 4. Layout and status bar

### English in a Chinese chrome

**File:** `App.tsx:36, 105, 109, 117, 273–274, 299, 306`

| String | When the user sees it |
|---|---|
| `Ready` | idle footer; `/kill` spinner (tour 224, 256) |
| `Awaiting approval` | Linux PTY approval footer |
| `Running read` | brief `tool_start` |
| `Cancelled` / `Stopped` | `done` without task, or `runTask` catch |
| `CURRENT TASK` | dual pane ≥120 cols (Linux wide snapshot) |
| `read-only` / `workspace-edit` | header |
| `api.openai.com` | **demo** header (tour line 2) while the product is offline |

Demo should not show a live API host.

### Footer vs right pane vs `/task`

100×32 tour is single-column (`dual` at 120, `App.tsx:25`). Footer: `已回答 · 未验证 · turn 2 · tokens ~2,174` — no remaining budget, no checkpoint, no stop reason. Those exist only in the 28-col pane or `/task`. Pane tool count is **session transcript length**, not `run.toolCalls/max` (`App.tsx:301` vs `transcript.ts:139`).

`/task` in the tour: `最近检查点：stopped`, `停止原因：completed`, `Tokens：~2,174/100,000 · 剩余 97,826`. Useful numbers, buried in a `!` blob, enums not translated.

### Transcript density

Every entry adds a blank line (`transcript.ts:225`). Failed tools dump full `content` (`:214`) — Linux deny shows the JSON args plus `permission_denied`. Success is one line until Ctrl+O, which explodes every call. `/help` is ~16 lines of scrollback forever. ISO timestamps (`2026-09-29T02:22:42.856Z`) in `/sessions`. Session UUIDs wrap (`linux-pty-transcript.txt:137`).

### Resize / 80 cols / colour

80×24 smoke (`pty-smoke.py:37, 189`) checks dual-pane `│` at 140 and idle prompt. It does not check 80-col `/task`, approval, or footer. `NO_COLOR=1` is documented; Ink still emits `color=` props (`App.tsx` throughout). CLI tests set `NO_COLOR`; UI tests do not assert a colourless frame.

Status+header glued on one dump line (tour 226–227) is consecutive Ink paints, not a wrap I would ship as a layout bug.

## Top 8 UI changes next

1. **[medium]** While a run is active, replace `输入你的目标…` with a persistent `运行中 · 仅 /ps /kill · Esc 取消` line, and make the first Esc clear a non-empty draft, the second Esc abort the run.
2. **[small]** Map every user-visible status and tool error (`Ready`, `Stopped`, `Awaiting approval`, `Running $tool`, `process_not_found`, `read_only`, `permission_denied`, `token_budget`, `verification_failed`, `/ps` `running`) to Chinese, including `/task` checkpoint/reason.
3. **[medium]** In read-only/demo, refuse `/verify` up front with “当前只读/离线，无法执行 bash 验收”, and never mount a composer that will swallow `y`.
4. **[small]** `/kill` copy: require `icy-process:` or an 8-char prefix; if the token looks like a pid, say so; `/ps` should highlight the kill id, not the pid.
5. **[medium]** Render `/help`, `/task`, `/ps`, `/sessions` as a transient pager/overlay (like Claude Code) instead of append-only `!` notices.
6. **[small]** Approval: keep the host-escape sentence on detach; spell out that A is exact command+cwd+timeout+detach and dies on `/new`; name the processes directory and 30‑minute cap.
7. **[small]** `/sessions` must show 状态; `/help` must list Y/A/N, Esc vs Ctrl+C, `/kill` ids, and `/verify` read-only limits.
8. **[medium]** Queue one follow-up message during a run (Claude Code behaviour) instead of the after-the-fact `只接受 /ps 和 /kill` notice; keep `/task` `/thinking` `/help` available while busy.
